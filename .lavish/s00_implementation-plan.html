Facts that shape the design

  • nmp-dsci is a GitHub user, not an org — there is no account-level webhook. Hooks must be installed per repo (scripted) or via a GitHub App.
  • Several repos (ConvFinQA-agent, DABStep-loop, data-qa-agent…) push only to the no-mistakes bare remote — local git must be a source, GitHub alone misses commits.
  • Every Claude Code assistant line carries cwd, gitBranch, model, version and full usage (incl. thinking_tokens, cache 5m/1h split). Project attribution is free.
  • Claude Code hooks (SessionStart/Stop/PostToolUse) give live events but no token counts — JSONL stays the source of truth for tokens.
  • AWS account 089783391188 already has the GitHub OIDC provider and a tfstate bucket; transcript-rag-agent is the App Runner template to copy.
  • AWS CLI has no active credentials right now (aws login needed before terraform).

2 · Proposed architecture

Pull-first collectors on the laptop, an append-only event store in S3, DuckDB rollups, and one read-mostly App Runner service. Webhooks are an accelerator for GitHub/AWS, never the only path — backfill is always possible.

Kinds by source

  • claude_code: session_start · assistant_message · tool_use · session_end
  • codex: session_meta · token_count
  • git_local: commit · branch_switch
  • github: push · branch_created · branch_deleted · pr_opened · pr_merged · review · workflow_run · deployment_status
  • aws: apprunner_deploy · ecr_push · daily_cost
  • lavish: page_created · page_updated
  • evals: run

Privacy invariant

No field may carry prompt or transcript text. File paths are kept (they're the project signal); prompt text is dropped at the collector, never hashed-and-stored. Tests assert this on every fixture.

5 · "Building vs evals" — how a session gets classified

Two tiers, cheap first. Tier 1 is deterministic and runs in the collector; Tier 2 only runs on sessions Tier 1 can't place, and only over metadata.

Tier 1 · path & tool heuristics (free, deterministic)

  • Files touched by Edit/Write: evals/, tests/, *_eval*.py, runs/ → evals
  • src/, frontend/, app/ → building
  • infra/, *.tf, Dockerfile, .github/workflows → infra
  • .lavish/, *.md, docs/ → writing
  • Zero edits, many Read/Grep → review
  • Majority vote per session; ties → Tier 2

Tier 2 · Haiku tagger over metadata (cents)

  • Input: project, branch, tool sequence, file-path list, session length. Never the prompts.
  • Output: one class + confidence, cached by session_id
  • Batched nightly; ≈ 300 tokens/session → negligible cost
  • Class is stored on the event so rollups never re-classify

Later: a "correct this label" button in the UI writes a label_override event — the same store, no special path.

8 · Decisions to make decide

Each form queues one answer. Recommendation is pre-selected; change it if you disagree, then press Queue answer. Press Send to Agent when you're done with all of them.

D-01 Storage engine

recommended

A · S3 JSONL + DuckDB/parquet

Fits: append-only events, analytical reads, multi-instance App Runner, demo snapshot baking.

Cost: ≈ $0/mo (S3 pennies). Ops: none.

Pays for it with: minute-level freshness (rollup cadence), no row-level updates — corrections are new events.

B · Postgres (Neon / RDS)

Fits: real-time drill-down, ad-hoc SQL in a client, mutable labels.

Cost: Neon free tier or RDS ≈ $15/mo. Ops: migrations, a secret in App Runner, a vendor.

Pays for it with: the demo can no longer be a keyless read-only image.

C · SQLite + Litestream → S3

Fits: single-file simplicity, works offline.

Cost: ≈ $0. Ops: restore-on-boot.

Pays for it with: single writer — breaks the moment App Runner scales to 2 instances or a webhook and a collector write at once.

D-02 What the public demo exposes

recommended

Aggregates only

Counts, tokens, $, per project and per week. No session ids, file paths, branch names, or commit messages. Real data, safe shape.

Full detail, live

Everything you see privately, public. Strongest portfolio story; leaks working patterns, branch names, project codenames.

Synthetic snapshot

Demo runs on generated data. Zero leakage; also zero credibility — visitors can tell.

D-03 GitHub capture (user account → no org webhook)

recommended

Per-repo webhooks, scripted

pt github install-hooks loops over gh repo list nmp-dsci and creates/updates one hook each with the shared HMAC secret. Re-run when a repo is added. Plus REST backfill.

GitHub App

One webhook URL, auto-covers new repos, fine-grained permissions. Costs a private key to manage and an install flow — right answer at 50+ repos, heavy at 21.

Poll only

Hourly gh api backfill, no webhooks. Simplest; loses workflow_run/deploy granularity and CI duration precision.

D-04 Stack

Recommended: Python 3.12 + FastAPI + DuckDB backend, Vite + React + TS frontend — identical to transcript-rag-agent / data-qa-agent so Dockerfile, CI and terraform copy over unchanged. Alternative: TypeScript end-to-end (Node + DuckDB-node) — one language, but nothing in the portfolio to copy from.

D-05 Which sources are in v1? tracked batch

D-06 Claude Code live hooks in v1?

Hooks in ~/.claude/settings.json (currently none configured) would post SessionStart/Stop to the API for a live "working on X now" indicator. They add no token data and a network call to every session. Recommendation: defer to P7; the 5-minute collector is fresh enough.

9 · Risks & failure modes

Price table drift. Cost is derived, not observed. Keep enrich/prices.yaml dated per model; rollups store the price version used so history doesn't silently restate.
Claude Code JSONL shape changes between CLI versions (version is on every line). Parser is version-tolerant: unknown fields ignored, missing usage skipped, one fixture per shape seen.
Project attribution relies on cwd. Worktrees, scratchpad dirs and ~/git/nmp-projects vs nmp-ai-portfolio moves need a path→project map in config, not heuristics.
Vanity metrics. Tokens are an input, not an output. Every view pairs effort with a shipped-thing count; the Ship log is first-class so the app can't become a token leaderboard.
Leak by accident. A collector that copies a content field is the failure mode. A test scans every fixture-derived event for any string > 200 chars and fails the build.
AWS auth. No credentials active locally right now; bootstrap terraform needs an aws login first. Everything through P5 works without AWS.
