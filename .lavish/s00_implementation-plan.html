Facts that shape the design
  • nmp-dsci is a GitHub user, not an org — no account-level webhook exists. Hooks go per repo (scripted) or via a GitHub App.
  • Several repos (ConvFinQA-agent, DABStep-loop, data-qa-agent…) push only to the no-mistakes bare remote — local git must be a source.
  • Every Claude Code assistant line carries cwd, gitBranch, model, version and full usage (incl. thinking, 5m/1h cache split). Project attribution is free.
  • Claude Code hooks give live events but no token counts — JSONL stays the source of truth.
  • AWS 089783391188 already has the GitHub OIDC provider + tfstate bucket; transcript-rag-agent is the App Runner template.
  • No AWS credentials active locally right now (aws login before terraform).
Proposed

Architecture

Pull-first collectors on the laptop, an append-only event store in S3, DuckDB rollups, one read-mostly App Runner service. Webhooks accelerate GitHub/AWS; backfill is always possible.

Contract

Event schema v1

{ "event_id": "sha256(source + natural_key)", // idempotent re-runs "schema": 1, "source": "claude_code", "kind": "assistant_message", "ts": "2026-09-15T07:54:11Z", "project": "DABStep-loop", // from cwd / repo path "repo": "nmp-dsci/DABStep-loop", "branch": "main", "session_id": "551c7a2d-…", "model": "claude-haiku-4-5-20251001", "tokens": { "input": 10, "output": 506, "cache_read": 30221, "cache_write": 0, "thinking": 247 }, "cost_usd": 0.0032, // from enrich/prices.yaml "tools": ["Bash", "Edit"], "class": "building", // building | evals | infra | writing | review "meta": { "version": "2.1.259" } }
Kinds by source
  • claude_code: session_start · assistant_message · tool_use · session_end
  • codex: session_meta · token_count
  • git_local: commit · branch_switch
  • github: push · branch_created · branch_deleted · pr_opened · pr_merged · review · workflow_run · deployment_status
  • aws: apprunner_deploy · ecr_push · daily_cost
  • lavish: page_created · page_updated
  • evals: run
Privacy invariant

No field may carry prompt or transcript text. File paths are kept (they are the project signal); prompt text is dropped at the collector, never hashed-and-stored. A test asserts this on every fixture.

Two tiers, cheap first

Building vs evals

Tier 1 is deterministic and runs in the collector; Tier 2 only runs on sessions Tier 1 can't place, and only over metadata.

Tier 1 · path & tool heuristics

free · deterministic
  • Edit/Write into evals/, tests/, *_eval*.py, runs/ → evals
  • src/, frontend/, app/ → building
  • infra/, *.tf, Dockerfile, .github/workflows → infra
  • .lavish/, *.md, docs/ → writing
  • Zero edits, many Read/Grep → review
  • Majority vote per session; ties → Tier 2

Tier 2 · Haiku tagger over metadata

cents · nightly batch
  • Input: project, branch, tool sequence, file-path list, session length. Never the prompts.
  • Output: one class + confidence, cached by session_id
  • ≈ 300 tokens/session → negligible cost
  • Class is stored on the event so rollups never re-classify

Later: a "correct this label" control in the UI writes a label_override event — same store, no special path.

Dark mode

Same system, inverted ground

Follows the OS by default; the header toggle overrides (system → dark → light, remembered per browser). Ground #141414, paper #1C1C1C, ink #EFEFEF, hairlines #3A3A3A. Wine and foil tones do not change. Primary button and "hot" surfaces use --inv (#2C2C2C) so they stay readable.

0px radius · 1px hairlines · no shadows

Cards are cells in a hairline grid, not floating boxes. Sections alternate grey ground / white paper. One full-bleed split hero per top-level view: image or data-art left, wine panel right with centred copy and ghost buttons.

D-04 · open · you asked "why Python, why not TS the whole thing?"

Stack — the honest comparison

Python + FastAPI + DuckDB · React/TS front

Why I picked it: not language merit — copy-ability. transcript-rag-agent and data-qa-agent already have the Dockerfile, CI, OIDC deploy workflow and App Runner terraform for exactly this shape. P6 becomes a rename instead of a build. DuckDB's Python API is the reference implementation; boto3 and the anthropic SDK are boring.

Costs: two languages, two toolchains (uv + npm), API↔UI types duplicated by hand or via OpenAPI codegen.

TypeScript end-to-end · Node 24 + Hono/Fastify + @duckdb/node-api · React

What it buys: one language, one toolchain, shared types between collectors, API and UI (zod schemas = event schema = API contract), Vitest everywhere, and the hooks/scripts Claude Code and Codex expose are JS-native. The collectors are JSONL parsing + git + fs — TS is at least as good at that.

Costs: nothing in the portfolio to copy — Dockerfile, CI and deploy workflow written fresh (≈ a day); @duckdb/node-api is solid but younger than the Python binding; AWS SDK v3 is more verbose than boto3. None of these are hard, they are just not free.

Net: if this project is a tool for you, Python wins on time-to-App-Runner. If it is also a portfolio piece showing a TS/Node service in AWS (you don't have one yet — every sibling is Python), TS end-to-end is the better story and the extra day is worth it. I'd take TS if you want the portfolio angle; I have no other reason to prefer Python.

Honesty

Risks & failure modes

Price table drift. Cost is derived, not observed. enrich/prices.yaml is dated per model; rollups store the price version used so history never silently restates.
Transcript retention. Claude Code purges transcripts after 30 days by default; tokens older than that are gone for good. Mitigation: raise cleanupPeriodDays, collect every 5 min, treat history.jsonl as the backfill source for sessions/prompts.
Claude Code JSONL shape changes between CLI versions (version is on every line). Parser is version-tolerant: unknown fields ignored, missing usage skipped, one fixture per shape seen.
Project attribution relies on cwd. Worktrees, scratchpad dirs and ~/git/nmp-projects → nmp-ai-portfolio moves need a path→project map in config, not heuristics.
Vanity metrics. Tokens are an input, not an output. Every view pairs effort with a shipped-thing count; the Ship log is first-class so the app can't become a token leaderboard.
Leak by accident. A collector that copies a content field is the failure mode. A test scans every fixture-derived event for any string > 200 chars and fails the build.
AWS auth. No credentials active locally; bootstrap terraform needs aws login. Everything through P5 works without AWS.
